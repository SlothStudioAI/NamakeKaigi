# 設計メモ(NamakeKaigi)

このアプリの作りを、短くまとめたものです。コードを読む・直す人向けです。使い方は [README](../README.md) を見てください。

## 1. 何をするアプリか
Claude Code・Antigravity の agy・Codex の3つのCLIを、1つのチャット画面から呼び出し、返答を並べて見せます。AI本体は持たず、利用者のPCに入っているCLIを、**発言ごとに起動**します。

- C# / WPF / net10.0-windows(自己完結型で配布)
- 画面は MVVM。画面を知らない部分(`Services/`)は、インターフェース越しに差し替えられ、試験は画面なしで行える

## 2. フォルダの構成
```
src/NamakeKaigi/
  Models/       参加者・発言・設定(データだけ)
  Services/     CLIの実行・返答の解析・会議の進行・ログ保存・設定の読み書き。画面を知らない
  ViewModels/   画面の状態とコマンド。Services だけを使う
  Views/        XAML。コードビハインドは、見た目のためだけ
  Themes/       配色テーマ(色・角丸の変更はここだけ)
  settings.json 既定の設定(exeの隣にコピーされる)
src/NamakeKaigi.Tests/  xUnit。Services と ViewModels を、画面なしで試験する
```

## 3. 会議の進み方
1. 利用者が発言を送る → `ChatSession` が、宛先のAIごとに `IChatAgent`(`ClaudeAgent`・`AgyAgent`・`CodexAgent`)へ渡す
2. 各 Agent は、CLIを1回起動して、出力を逐次読み、`ChatProgress`(考え中・途中の文章・完了・失敗)として画面へ知らせる。CLIの起動・終了は `ProcessRunner` が受け持つ
3. 2回目以降の発言は、CLIの会話IDで続きから話す(Claude と Codex は resume、agy は会話IDを保存)。会話が消えていたときだけ、新しい会話でやり直す
4. 「全員」宛ては、**同時**か**〇〇が先**(先の人が答えてから、残りが同時に答える)を選べる。同じAIへの発言は、1つずつ順に処理する(待ち行列)
5. 発言と返答は、`MarkdownLogWriter` が、会議ごとのフォルダに Markdown と JSON で保存する

## 4. 権限の仕組み(読む／読み書き／全部)
段階ごとに、CLIへ渡す追加の引数を切り替えます(READMEの表を参照。値は `settings.json` で変えられます)。

- **読む**: 書き換えとコマンドを止める引数を付ける
- **読み書き**: Claude は道具を限り、Codex はサンドボックス(作業フォルダの中だけ)、agy は編集の許可モード。AIごとに、止められる強さが違う
- **全部**: 各CLIの「確認なしで実行」に近い設定

AIごとの違いは、画面の歯車(ハーネスの説明)と README に書いてあります。どの段階でも、アプリは「いまの段階」を、本文の頭に添えて、AIに伝えます。

## 5. 設定
- 既定値は exe の隣の `settings.json`。利用者の変更は `%APPDATA%\NamakeKaigi\settings.local.json` にだけ書く(既定を上書きする重ね読み)
- ファイルが壊れていたら、別の名前に退避して、既定の設定で起動する。書き込みは、一時ファイルに書いてから置き換える
- 変わりうる数値(タイムアウト、更新の間隔など)は、コードに直書きせず、設定から読む

## 6. 入っていないAIの扱い
起動時に、各CLIを(設定の場所 → PATH の順に)探します。見つからないAIは、カードを出さず、会議にも参加させません。1つも見つからないときは、案内の窓を出します(`Services/CliLocator.cs`)。

## 7. 安全のための決まり
- リンクのクリックでは、実行できるファイルを**実行せず**、エクスプローラーで場所を示すだけにする(`Services/LinkDetector.cs`)。ネットワーク共有(`\\サーバー\...`)は調べない
- CLIは、アプリの終了時・解析の失敗時にも必ず止める(見えないまま作業が続かないように)
- 予期しない例外は、アプリ全体の受け口で `error.log` に記録し、続けられるときは続ける

## 8. 試験
`dotnet test` で全件を流します。CLIの代わりに偽物(`IProcessRunner`、`IChatSession` の試験用の実装)を入れるので、AIのCLIが入っていないPCでも通ります。画面の描画に触れる一部の試験は、全体を流したときだけ、不定期に失敗することがあります(単独では通ります)。
